## 實作內容

- `app/lib/server/runtime-policy.ts`
  - `NETTOPO_PILOT_SITE_ID` 必填。
  - `NETTOPO_PILOT_USERS` strict validation：email 格式、唯一 email、role 僅 `admin|engineer`、version 必填。
  - Pilot profile 下 demo auth、dev identity header、demo seed 維持 fail closed。

- `app/lib/server/pilot-session.ts`
  - `pilotSiteId()` 不再 fallback。
  - `parsePilotAllowlist()` 改 strict parser，避免 invalid entry 被靜默略過。

- `app/lib/server/pilot-policy.ts`
  - 新增 `expectedDbRoleForPilot()`、`isPilotSubjectBound()`、`canPilotUseFullExport()`。
  - `canPilotEngineerCreateSyntheticCustomer()` 改要求 DB role 必須為 `engineer` 且 assigned Pilot site。

- `app/api/pilot/session/route.ts`
  - 新增 `createPilotSessionPostHandler()` dependency seam。
  - 發 cookie 前驗 allowlist principal、active DB user、DB role、Pilot site。
  - unknown/unprovisioned/disabled/role mismatch/site mismatch 統一 401 `AUTHENTICATION_REQUIRED`，不發 cookie。
  - DB unavailable/schema not ready 使用 safe typed 503。
  - 成功 response 只回 email、pilotRole、TTL；session value 僅進 `Set-Cookie`。

- `db/topology-postgres.ts`
  - 新增 `loadPilotSessionUser(email)` 作為 Pilot login 的 active DB subject lookup。

- `app/api/topology/route.ts`
  - POST 改為 identity/auth first，再執行 Pilot same-origin/JSON check、body validation、repository mutation。
  - unsupported action 補 no-store/security headers 與 typed safe body。

- `app/api/credentials/route.ts`
  - POST 改為 identity/auth first，再執行 Pilot same-origin/JSON check、Zod validation、repository mutation。
  - Pilot Engineer credential write/read deny 維持，不回 plaintext/ciphertext。

- `app/page.tsx`
  - Pilot full export gate 改為 flag + `currentUser.role === "boss"`；Engineer 即使 flag=1 仍 disabled。

- Tests
  - 新增 `tests/pilot-session-handler.test.mjs`。
  - 更新 `tests/pilot-checkpoint.test.mjs`、`tests/pilot-internal-boundary.test.mjs`、`tests/runtime-policy.test.mjs`、`tests/request-identity.test.mjs`。

## QA_PIL_001 退回最小 RBAC 修復紀錄

- 日期：2026-08-20

- 結果：兩個 RBAC repository regression 已修復，DEV_PIL_001 回到 `READY_FOR_QA`

### 修復項目

- `createTopology` hidden-resource precedence：
  - non-Pilot／Pilot 都先驗 target site/customer 存在與 caller 對 customer+site scope 的可見性。
  - missing customer、invisible customer、unassigned/invisible site 都回 `Resource not found.`，避免以 403 洩漏站點或 Customer 存在。
  - create permission 判斷延後到 scope 可見性之後；transaction 內同樣先重驗 active user/resource/scope，再判斷 create permission。
  - Pilot principal mismatch 仍優先 generic 401；不放寬 Boss-only Customer mutation、Pilot-only Customer、Pilot site 或 Engineer owner/site 規則。

- Credential read-vs-write 語意：
  - topology missing、caller 不可讀、Pilot 跨站維持 `Resource not found.`。
  - topology 可讀但 caller 不可寫 topology 或缺 `credential.write` 時回 `Permission denied.`。
  - transaction 內同樣先重驗 readable，再判斷 writable/permission。
  - Pilot Engineer deny、Admin 只限 Pilot site、masked read/secret boundary 均未放寬。

- 新增行為測試：
  - `tests/rbac-precedence.integration.test.mjs`
  - 覆蓋：可讀不可寫 credential = 403、不可讀/跨站 credential = 404、unassigned createTopology = 404。
