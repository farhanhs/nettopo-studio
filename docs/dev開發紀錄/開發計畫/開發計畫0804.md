# NetTopo Studio 內網佈署與實戰反饋累積計畫

**建立日期**：2026-08-04  
**文件目的**：規劃 NetTopo Studio 在公司內網快速佈署上線、推廣與收集內部使用者反饋之執行計畫。

---

## 🎯 策略目標與核心心法

針對 NetTopo Studio 目前的架構（支援 IndexedDB 單機存取 與 PostgreSQL 團隊協作/權限控管/資密加密模式），採取 **「先輕量推廣、累積反饋、再逐步整合系統」** 的三階段漸進式佈署與推廣策略。

---

## 🚀 第一階段：快速內網佈署（24~48 小時內上線）

根據公司 IT 資源狀況，提供以下兩種佈署選項：

### 方案 A：Docker Compose 容器化全功能佈署（推薦 🌟）
適合已具備 Linux / Windows Server VM 或 Docker 環境之情境。

1. **補充生產環境 Docker Compose (`docker-compose.prod.yml`)**：
   結合現有 PostgreSQL 17 與 Node.js 應用服務。
2. **環境變數設定 (.env.production)**：
   ```env
   NEXT_PUBLIC_TOPOLOGY_STORAGE=server
   DATABASE_URL=postgres://nettopo:YOUR_SECURE_PASSWORD@postgres:5432/nettopo_studio
   NETTOPO_CREDENTIAL_ENCRYPTION_KEY=<32-byte Base64密鑰>
   PORT=3000
   HOST=0.0.0.0
   ```
3. **內網服務綁定**：
   在內網伺服器執行打包啟動，綁定內網 IP（例如 `http://192.168.x.x:3000`）或內網 DNS（例如 `http://nettopo.company.local`）。

### 方案 B：純前端靜態頁面部署（極速零資安疑慮試用）
若 VM 申請流程較長，可先以 **IndexedDB 模式** 極速釋出：
1. 以 `NEXT_PUBLIC_TOPOLOGY_STORAGE=indexeddb` 打包產出前端靜態檔案。
2. 佈署至內網現有的 Nginx / IIS / Internal GitLab Pages。
3. **特點**：同仁打開瀏覽器即用，資料儲存於本地瀏覽器，可利用 JSON 匯出/匯入交換拓撲檔。

---

## 💬 第二階段：建立快速反饋與種子試用機制

為了提升同仁使用意願並精準收集改進建議：

### 1. 預填「種子範例拓撲 (Seed Topology Data)」
* **關鍵心法**：不讓使用者面對空白畫面。
* 預置 1~2 個標準範例（如「總部核心機房架構」、「北一站網絡拓撲範例」）。
* 同仁進入系統即可體驗：自動排版 (ELK)、切換 VLAN、機密遮蔽 (Credential Masking)、權限控管 (測試身分選擇器) 與 PDF 匯出。

### 2. 界面內建「一鍵意見回饋 (In-App Feedback Banner)」
* 在 UI 右上角/側邊欄新增 `💬 意見回饋 / 功能許願` 按鈕。
* 導向內網 Google Forms / Microsoft Forms / Issue 追蹤單，填寫欄位包含：
  * **使用情境**（如例行維運、向主管報備、資產清查）
  * **滿意功能與痛點**
  * **期望新增功能**

### 3. 邀請 3~5 位「種子使用者 (Pilot Users)」進行 15 分鐘 Playtest
* 邀請網路工程師、資安 MIS、機房維運人員與專案經理進行試用。
* 記錄繪圖與操作流程中的痛點（如設備圖示、IP 格式驗證等）。

---

## 🛡️ 第三階段：資安防護與正式系統整合（1~2 週內）

當反饋收集完成並準備擴大至全公司使用：

1. **開啟 HTTPS 加密連線**：
   系統包含內網 IP、MAC、密碼等敏感資料，前端需透過 Nginx / Traefik 掛載內部 SSL 憑證。
2. **PostgreSQL 定時備份機制**：
   設定 Cron Job 每日執行 `pg_dump` 備份數據庫至內網 NAS。
3. **SSO / 公司帳號單點登入整合**：
   將現有的 `測試身分` (x-nettopo-user-email Header) 接入公司 LDAP / Azure AD / OIDC。
